# Task009 独立保留内容评估计划

## 身份与评估边界

- 编写时点：Task009运行前。执行者为独立held-out内容评估者，不是runtime专家。本文件不是应用输入、提示词、检索资料、自动评分器或运行关卡，不向runtime发送本计划及检查答案。
- 本次用户授权的测试是原始资料及可验证OCR起步的自主反馈测试，不提供人工参考报告、Task006/007草稿、旧评分结果或本评估标准。授权运行由Main执行；本评估者不调用模型、不改应用/输入/DB、不回答业务问题。
- 运行前约定不等于已验证隔离。运行后只查Main提供的输入清单、provenance及必要初始化证据；若发现旧草稿/历史缺陷清单进入模型上下文，记录污染范围，不据此宣称fresh-run自主纠错。
- 本轮只创建本文件。运行后Main提供精确report/result ID、正文/导出物及相关trace，再执行独立分析；不主动轮询运行。

## 事实基线与不作真值的材料

- 原scope：第一合同段全线路堑高边坡总体施工安全风险评估；完成范围内所需内容，具体评分体系需后续与项目负责人确认。资料汇编不是新设计或工程签发。范围外合同段的内容不算遗漏；不擅自把全线路范围收窄为仅某六处或仅主线，疑似对象按原始资料与适用判据核实。
- 真值分层：原件支持可核查记载；指南支持规则文本；独立确定性复算支持给定输入的算术；有权人工明确答复才支持已确认的业务决定。原件互相矛盾时无唯一事实答案，不替负责人裁决。
- runtime共享事实、模型解释、review意见、计算工具回执均是待审证据，不是真值。工具算对不证明输入、单位、权重、选档和适用性正确；review接受不证明正文正确。
- 复用Task006/007中已经核实的原始来源定位及缺陷类型，不复用人工报告内容/结论。旧六个总分不设为期望答案；本轮可采用不同的有据输入或明确不计算，但不能用未读取或空泛待确认逃避已有资料的基本工作。

## 分类与计数

每个独立问题记录：对象/规则、最早可见正文证据、反馈事件、后继改动、最终状态及可核验出处。按问题而非重复段落、专家人数或工具次数计数。

| 分类 | 所需证据 |
| --- | --- |
| prevented error / 首次可见版本避免 | 相关内容已被实质处理，首次可见版本即符合原始证据/规则且最终仍符合。只说明未观察到该历史错误复现，不宣称反馈机制因果预防；中间版本不完整时不得断言从未出错。 |
| independently detected + corrected / 自主发现并修正 | 本轮自产内容先存在可独立确认的错误，runtime在未获得本评估反馈前明确检出；后继正文、汇总和结论实际修复并经独立核验。需有前后result ID、反馈事件及对应段落，只有review建议或自称已改不计。 |
| new defect / 本轮新缺陷 | 本轮出现且原证据证实的问题，标注首次出现阶段、是否由修订引入、是否残留。历史同类重现另标“已知类型复现”，不包装成新发现；自主检出但未修正单列，不能计成功纠错。 |
| false alarm / 误报 | runtime提出的具体缺陷指控被原证据/独立复算反驳；合理待核实疑问、不同可接受方案、范围外不写不自动算误报。记录有无引发错误修改。 |
| unassessed / 未评估 | 缺少精确正文、必要源页、轨迹或该业务前提不成立；说明缺口及影响。不把未检查、缺图未读、无输出计作避免错误或通过。 |

本轮没有注入旧缺陷稿，因此不存在“检出历史注入缺陷”的成功数。缺陷是否新颖与是否修复是不同维度；同一问题可记录其发现/修正过程，但最终成功数只计一次。无错误可供纠正时，不据此判自主纠错失败，也不声称纠错能力已验证。
