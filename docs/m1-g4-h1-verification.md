## Result and boundaries

New host preparation captures immutable scope/outline sources and creates a
requirement record before the Coordinator plans. The record initially marks every
anchor unresolved. Coordinator proposals can change interpretations and applicability,
but cannot replace or omit anchors. Approval explicitly confirms the exact requirement
version, including proposed not-applicable items.

A shared completeness check applies to plan saving/submission, approval and approval
replay, writer authorization, assessment/outcome persistence, and Word/Excel export.
Export checks the selected snapshot's own plan and confirmation; a cached export
receipt cannot bypass a revised requirement record. Existing historical documents
and successful pre-H1 outcome receipts remain readable without rewriting them.

Required table roles are data declared by the requirement record. The change does
not add a five-slope constant or a new calculation/table renderer. Non-scoring
commissions require explicit dispositions and owner confirmation. The historical
presentation-contract guard remains only for old cases without the new contract;
all newly prepared hosts use the independent requirement record.

## Execution limits and remaining work

Tests run on the existing native Linux Python environment with synthetic fresh
cases. The broader regression reuses the offline network fence and old-input access
guard, extended to the stopped native G4 run, financial storage and original customer
inputs. A normal Python child probe confirms protected-file, SQLite and external-DNS
denial. This is a Python audit fence, not an OS sandbox for isolated Python/native
children. The separate actual-source audit deliberately imports only the two
original inputs into a fresh scratch case and denies network/subprocess calls.

Unsupported outline numbering and table-contained structure remain explicit
unresolved items. Images are not OCRed or semantically interpreted by this parser.
This patch does not claim arbitrary Word-layout support, agent autonomy or engineering
sign-off. Planning tools, prepared-data attachment and fixed-text extraction are H2;
real-attempt replay, source-access coverage, scripted completion and the full suite
are H3. No paid call, report restart, ledger change or email is part of H1.
