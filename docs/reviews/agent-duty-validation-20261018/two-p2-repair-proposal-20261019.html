1. 恢复任务：原始契约与本次指令分开表达

已证根因：新指令已传入，但程序仍把原goal作为当前权威；摘要移出新Human后，当前状态读取也不能还原本次完整指令。这是同一机制的4个失败，尚未证明真实模型一定会照旧执行。

方案：保留原任务及所有权，在现有调用绑定中保留本次经过校验的完整指令；每次实际调用均更新绑定，退出后复原。当前状态、摘要上下文和任务读取共用这一来源，清楚区分初始契约和当次行动指令。

边界：覆盖恢复、摘要和同一任务后续调用。新指令不能扩大权限或改写已保存审核范围；不新增“最新任务”库，不覆写原goal，不修改摘要模型、角色prompt或独立文字工具的内容策略。

2. 成功缓存：同一收据可由不同操作安全复用

已证根因：新operation复用了已有分析，程序却再次INSERT同一收据主键，事务失败。inline、offload、legacy的3个失败属于同一机制；原始模型调用仅1次。

方案：保留现有operation、分析缓存和receipt三种身份。在同一事务内核对父操作仍是本次保留的状态，再检查收据：不存在则插入，完整记录一致则复用，不一致则明确报告冲突；最后原子完成新操作。

边界：只调整成功结果落账，旧receipt和ID不变。不使用覆盖/忽略冲突的SQL，不为复用再调模型，不自动放行历史reserved或unknown，不修改模型、预算或重试规则。

# 两项P2最小修复提案（Neo，待用户确认）

**本轮只做设计，没有改应用/测试、没有运行测试或调用付费模型。**保留现有7个失败用例及原判据、54个通过控制。目标是消除两处已复现机制，不恢复C1/batch1重构，不重跑客户报告。完整字段、7个nodeid与源码基线SHA见同名JSON。

## 一、D-RESUME-01：原任务不动，可靠表达本次实际委托

问题不是原goal应当删除，而是程序把它当“当前全部权威”，本次改委托仅存在易被摘要移出的Human中。建议保留DelegatedTask@1、owner、review范围、layout grant、历史；在**已有绑定**里携带本次实际native description，所有当前状态读取使用同一来源。

最小内部表示（均为拟议，不是现有API）：`delegate_operation_id`、完整`description`、`description_sha256`。已有actor绑定继续负责身份/权限，不增模型可设置参数。原`assignment`保持原样，并明确它是初始契约；新`current_invocation`明确本次行动指令，不能扩大原权限或改变已保存审核范围。

具体代码：

|拟改文件/入口|改什么|
|---|---|
|content_tasks.py / delegated_task、现有_binding|在原委派operation验证成功后绑定本次文字与call身份，提供检查workspace/actor/task的只读取值；退出reset。|
|deep_runtime.py / BusinessBoundary.invoke_native（约253–274行）|每次真正handler调用均绑定实际next_call文字，finally复原；不能只绑定最初description。|
|task_context.py / exact_task_context|区分原assignment与本次invocation；去掉“旧goal可无条件压倒本次委托”的整体表述。|
|decision_state.py / compact_context|当前指令全文与来源不经通用preview裁剪，read_decision_state沿同一exact上下文读取。|
|hierarchical_tools.py / read_task_assignment|仍返回原assignment/readiness，同时明确本次指令；不向Writer/Layout新增该工具。|

**关键相邻路径：**task_supervision约745行会用同一个call.id发起不同description的completion follow-up。因此要在每次invoke_native重新绑定，description SHA区分实际文字，不改task identity。这里仅重绑现有server supervisor产生的有效文字，不拿修改后的description重新登记同一delegate operation（那应当触发冲突）；原始委派校验保持。WorkingSummary约137行本已读取compact_context(exact_task_context)，可直接复用，不需再造摘要恢复库或要求summary模型逐字记住任务。

**平台核查：**本机DeepAgents0.7.19、LangChain1.4.2/core1.6.5、LangGraph1.2.12。已读安装的subagents.py约770–865行：isolated task把description放入HumanMessage再调用原subagent；本次文字不是框架自动维护的独立业务状态。既有ContextVar、middleware、原生checkpoint与状态reader足以作为首选修复挂点，不新建Agent循环。

**恢复约定：**本次文字来自已经校验的真实native call；parent/tool checkpoint重入必须先重放该call的权限/operation校验，再重建绑定。ContentStore.operation只有request_digest/response，**没有保存description全文**，不能拿它假充恢复来源。不按时间查“最新任务”、不从summary或普通Human猜权威。无合法绑定的直接child入口仍FORBIDDEN。真实child checkpoint重入须新增fake控制确认，当前仅设计，未验证。

**并发与权限：**嵌套ContextVar token按协程隔离，正常、异常、async取消均reset。原task、grant、review scope、followup次数与unknown不重放不变；新文字不取得新权利。只改变Agent/summary的当前任务表达，不顺带改独立文字工具commission/authority digest，不使旧候选收据失效。

不采用：只改System标签（R02仍会丢全文）；覆写原goal/每次新owner（破坏历史及所有权）；最新invocation表或新工作流（平行真相与竞态）；新增自定义Agent状态通道（现有机制尚未被证明不足）。本次全文不另设固定字符上限，仍受真实模型容量准入；不把全部资料塞入上下文。

## 二、D-TEXT-CACHE-01：相同内容收据复用，外操作各自原子完成

三个身份保持区分：外operation由actor+operation_id识别；原始分析由输入/prompt/model/contract识别；owned receipt继续使用现有actor/request/payloads/notes digest。**不改receipt_digest，不把operation_id加进原始请求，不重复模型调用。**

只拟改`text_work.py / produce`约413–492行的完成事务：

1. 保留原始reserved父记录作为CAS期望。完成时在现有`BEGIN IMMEDIATE`内重读；必须与该保留值、actor/request身份一致，禁止盲目覆盖其他状态。
2. receipt不存在才INSERT；已存在且是**完整相同的completed stored记录**才复用，原行一字不改。核身份、请求、输出、authority/evidence、refs/selections、revision、notes，不以相同body或“语义差不多”作为依据。比较解析后的完整记录，不比较JSON键顺序；原cache保留的model/usage/duration等来源也须一致。缺少历史字段不自动补齐或覆盖以求一致；不同记录保留并明确拒绝。
3. 收据不一致就明确本地receipt identity冲突，保留旧收据、不完成新父，不用OR REPLACE或盲IGNORE掩盖。沿现有诊断/events保留local integrity阶段与已收raw response事实，不称provider unknown，也不赋予自动重试权。
4. 原子完成匹配的父记录与收据insert/已验证复用。事务失败则回滚；同operation成功重放、原schema-only replay保持原逻辑。新operation的外层reused标记不强行指定；usage是原始调用来源，不重复计费。

**并发：**已有成功raw cache时，不同外operation的完成由SQLite串行，可共享同一完全相同receipt；不在DB事务中调用模型。不新增“等待/重试正在飞的raw请求”，现有reserve_once/unknown规则保持。父记录已被改变则CAS拒绝，不覆盖。receipt冲突时父保留reserved供检查，错误明确是本地完整性失败而非远端结果未知；不新增自动rearm。

**历史：**旧receipt ID、原行、raw input/response、owner、来源和预算未知保留。已经搁置的reserved父不会自动迁移或放行；是否恢复必须另有确切已收结果证据。此次修复不能宣称替所有历史中断状态解锁。

不采用：OR REPLACE（可能覆盖旧证据）、盲OR IGNORE（掩盖不同数据）、改digest加入operation（破坏候选/历史重放或制造重复调用）、捕获IntegrityError后直接算成功（未证身份与父操作完成）。不改共享evidence_analysis准入、未知处置或旧预算。
