独立格式fixture取自已归档《报告编制格式标准》2.2、3.1/3.3、4.1、7.2、10.1：上/下/左25mm、右15mm、装订线0；一级/二级/三级标题宋体加粗18/15/14pt，正文宋体12pt，表内中文宋体10.5pt、数字英文Times New Roman10.5pt；目录标题宋体加粗16pt，各级目录宋体12pt（一级加粗）；标题/正文/表格/目录1.5倍。保留标准封面项目名称等单倍行距例外。旧布局对照：右25mm、正文1.3、表格1.15。值来自标准，不是由当前导出器反推。
触发路径
F：合法参数→实际Word，分别正文/表格/目录/局部覆盖；R：实际Layout收到规范与旧参数，自主选择，后续在隔离fixture执行合法结果。
观察点
Agent收到的规范、实际export参数、DOCX section/styles/paragraph/table属性及真实页面。
判错依据
依据独立fixture核最终实际段落/表格/目录的有效字体字号、继承/直接格式、边距行距及合法例外，保留原文；不能只查样式名，也不能用“旧版一致”代替符合。F只证工具执行参数，R+产物才支持规范落实；若当前接口不能表达条款，记录能力缺口而非伪造参数或跳过报绿。字体不可用/渲染替代另记，不以DOCX属性代称实际视觉符合。
正常与相邻路径对照
原本已合规参数无需强制改动；局部表格1.5应与全局和继承值一致；不覆盖明确的合法例外。
如何证明测试能检出
恢复旧参数时符合性检查必须失败，即使新旧等价检查通过；字体/行距/边距分开诊断。
不能据此证明
程序参数测试不能证明真实Agent会选择这些参数；渲染成功也不是视觉验收。
