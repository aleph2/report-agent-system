## 复核追加问题及处置

三项关联 P2 在本轮一并修正：已登记复用随独立来源更新失效；被 supersede 的旧最终 S 不再提供正覆盖；纠正内容误判时允许原样保留尚未执行的成品检查。相应反例已加入测试。

成品缺陷的显式纠正必须覆盖原类目及同版本成品，不能通过遗漏旧页面 N 撤销它；旧页面记录也不能复用到新快照。未执行项保持 null，无须为纠正内容强制先做页面核查。

## 使用与兼容边界

启用方式仍是独立项目 manifest 的 `content_contract: hierarchical-review-v1`；旧报告路径保持。`content_final_review` 是保存的历史最终记录，`content_current_review` / CLI 的 `current_review` 表示当前适用结果。

以前没有记录成品检查的 S 不再算完整交付通过，应重新核查并保存新记录。此前按角色统一 owner 保存的委派成果保持可读；由于没有真实任务归属，不能自动授权新任务改写，若要继续写这些成果需另行明确归属迁移。新任务及原生重试/恢复采用持久任务身份。

设计中的文档修订谱系、手工 Word 新版本接入与映射歧义处理、前端新内容展示、真实模型对比与迁移验收仍未完成。本轮没有用五项缺陷修复代替这些能力的验收，也未修改 API key、模型或服务配置。
