用户已确认的C1方案 · 2026-10-18

状态：已确认、尚未实现。只记录设计，不改应用代码。

结合用户委托、适用要求和当前状态，明确本次工作的目标、范围、预期结果、约束及未决事项，并在后续决策和交接中保持这些信息一致。

结构化保存当前委托的明确解释，供后续职责使用；不复制一套需求、计划和进度。

字段含义
current_assignment
当前委托		本次要做什么，以及它与项目最终目标的关系；继续必须明确继续哪项工作。
expected_result
预期成果		本次应交出什么、用于什么；具体验收标准由C2维护。
scope
范围		必须包含的对象和内容、明确排除的事项；未找到资料不能自动变为范围排除。
basis
理解依据		用户请求、Requirement、适用指令及反馈的精确引用，以及对本次工作的关键约束；下游须可取得适用的有效原文，概括不能替代或削弱原要求。
open_questions
未决事项		尚未澄清的含义、冲突及其影响；没有则为空，不复制执行进度。

复用与边界

  • 项目最终目标继续使用现有goal；详细验收标准归C2，计划、委派和进度保留在各自现有状态中，不由C1重复维护。
  • 后续读取C1时须能够解析依据引用并读取适用要求的有效内容，不能只交付ID或用概括替代原要求。
  • C1是委托解释，不是授权；不能通过写入或修订解释批准付费、发布、扩大范围或修改他人成果。
  • 优先复用现有持久化状态机制；具体写入入口和字段类型在实施前明确，不先增加实体管理框架或固定工作流。
  • 结构化完整不证明意图理解正确；仍需核对用户目标是否保留及下游能否据此工作。

程序维护的元信息：所属项目及任务；理解依据的版本或摘要；解释的修订标识；记录时间。

更新规则

  • 新委托、要求变化或发现误解时更新；普通检索、正文生成和进度变化不必更新。
  • 恢复时核对当前委托及有效依据，不能只因最近保存而沿用；只重新评估受变化影响的理解和成果，不自动令全部成果失效。

状态：方案已确认；关键交接的保存位置与C4共同收敛，未改应用代码。

决定为了完成目标需要哪些资料、还需哪些工作及如何组织；不要求Coordinator先读完全部资料，也不是固定前置阶段。C3明确工作目标和分工意向，C4负责实际委派及责任绑定。

输入

  • C1当前委托、预期成果、范围、理解依据及未决事项。
  • C2适用Criterion及原始依据。
  • 资料目录、检索与读取结果。
  • 已有成果及任务状态、缺口、可用能力与适用经验。

输出与消费方

  • 资料读取、检索或独立LLM分析请求，交相应工具执行。
  • 选定材料的精确引用、版本、位置、用途和已知限制，供后续责任方使用。
  • 需完成的工作及划分，交C4明确每项解决的问题、采用准则、预期成果及必要依赖。
  • 缺口、矛盾和需人决定的问题，供Coordinator安排后续行动，必要时向用户澄清。

承接C1和C2

  • C1委托和预期成果用于决定组织哪些工作，不能把完善报告缩成重新导出已有文件。
  • C1范围和依据用于保留应覆盖对象及内容；未决事项只影响相关工作，不自动停止全部工作。
  • C2准则用于判断材料和成果缺口，影响首次生产，不能只供后续Reviewer使用。

已确认的补充要求

  • Coordinator组织而不包办专业判断；Writer判断章节与资料关系，Reviewer独立调查。初步选材不能代替其判断；绑定审核材料不足时反馈调整，不默默缩小审核问题。
  • 区分可访问、已读片段与足以支持工作；区分检索无结果、读取失败和资料确实不存在。
  • 工作划分面向成果和衔接，不把检索次数或读取文件数量当成完成。
