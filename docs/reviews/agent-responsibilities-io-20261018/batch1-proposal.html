把本次委托交到 Writer 和文字工具

先贯通一条真实程序链路，再检查交接是否完整。

待用户确认，尚未实施。 用户只要求先列边界、代码和fake LLM验证方案，确认后实施。本文件不是实施批准。
本轮没有修改应用代码或测试，没有运行应用测试或报告模型。

在一条真实报告程序链路中，本次委托、适用准则及明确选择的材料，能够从Coordinator交给Writer，再实际进入独立文字工具，而非依赖Writer每次凭记忆重述。

C1：保存任务理解→C4：绑定本次Writer委派→Writer：选择工作与材料→独立文字工具实际输入→原有精确保存

这是本批验证链路，不是新增固定业务步骤。Agent决定动作；程序负责忠实传递、精确版本、权限和持久化。

5个现有Python模块＋1个小领域模块，另2份现有角色说明最小同步；其余主要复用/回归。候选挂点不计已批准必改。代码行数与工期尚不能可靠给出。

具体例子与本批交付
目标
在一条真实报告程序链路中，本次委托、适用准则及明确选择的材料，能够从Coordinator交给Writer，再实际进入独立文字工具，而非依赖Writer每次凭记忆重述。
具体例子
合成委托要求输出一张表，保留指定表头/行及末尾条件，并遵守合成的右边距15mm要求。首批验证这些要求和原表选区确实传入文字工具；不声称本批会自动实现Word边距或模型会正确理解工程规则。
本批交付
C1可持久化并恢复；本次Writer调用的上下文可追溯；真实独立工具输入可核；原owner/精确采纳/旧receipt/unknown保护不回退。
证据边界
先证明程序传递与绑定，不证明真实Agent选材、理解标准或生成整份报告正确。

改动边界

包含

  • C1已确认五字段的最小schema、保存及现有状态读取。
  • C4仅Writer调用的最小上下文绑定；新任务和恢复原Writer两条路径。
  • C2复用已保存Criterion及关联Requirement的有效文本，不修改Criterion六字段。
  • C3复用精确材料Ref/现有SourceSelection/owned observation，不另存计划或原文镜像。
  • 共享解析结果到Writer有效输入、process_report_content实际commission及adoption一致性校验。
  • 旧模式不带新字段时的身份/归档packet兼容；Reviewer/Layout原契约不改。

  • 候选body无条件延后这一投影取舍；decision_data.py本批不因该建议默认修改。
  • 学习、发布、索引/RAG、Excel视觉、Word/XLSX同快照解耦、计算term绑定新字段。

  • 修复全部历史review发现、现有strict allOf或正常入口预算等其他待办；若妨碍本批fake入口，先报依赖，不顺手扩修。

当前记录

历史记录

程序绑定

沿用现有delegate:<native tool_call_id>的ContentStore.operation。在其成功结果中增加已解析writer_context身份/摘要，与同一个task_ref关联；不新增第二套任务状态。
执行身份
现有_binding继续由服务器持有Actor；可扩展同一绑定携带本次上下文指针，其他bound_actor使用方式不被改变。不得依赖Agent在objective中声明task_id。
精确版本
上下文按保存的C1/criteria精确版本解析，不默认取最新Criterion，不靠标题/字符串前缀找对象。
旧输入兼容
writer_context缺省/None在旧模式下从request完全省略；不向旧packet加入null/空对象，不改旧delegate/text-work request hash。
收据重放边界
已存在的delegate操作收据优先保持其原绑定；不能因后来新建C1而给旧调用偷偷补新上下文。
恢复绑定
正常native task恢复时，从原delegate操作收据重建本次binding；不读取一个“该task最近上下文”可变指针来覆盖历史调用。具体checkpoint挂点需fake反例确认。
新旧契约适用规则
  • 没有commission_understanding头且未传writer_context：保持当前legacy Writer行为；不自动迁移原case。
  • 新保存C1后，对没有既有delegate收据的新Writer调用，须显式传writer_context；缺失时在调用子图前返回有定位的契约错误。该依赖是输入契约，不规定额外资料/审核/排版步骤。
  • 已有旧delegate收据的重放保持旧绑定，不因新C1改变旧输入。
  • 旧checkpoint中尚无delegate收据的Writer调用若遇新契约，不自动升级或猜参数：明确拒绝并保留原记录；这类跨模式迁移不是本批自动恢复能力。
  • 本批writer_context传给Reviewer/Layout时明确拒绝；它不覆盖原review_requirements/layout_snapshot_ref规则。未传时两角色维持原行为。
恢复Writer
resume_content_task_id保持旧Writer task/owner；新调用可绑定新C1/准则上下文，随新的delegate operation保存。不直接改DelegatedTask@1或旧receipt，不因普通目标更新更换owner。旧审核契约仍不可变，本批不改。
实际模型输入
使用一个resolve_writer_commission helper生成同一语义结构。managed模式由TaskContext注入并提供现有精确读取路径；unmanaged模式在原生description附同一结构。两种表示均由同一解析结果生成，不能各自重写一套委托。材料正文仍走原证据路径。
完整性与容量
本批新委托字段不走通用递归裁短而丢失结尾约束；C1/已选Criterion是明确控制结果。若实际无法传递，应返回明确不完整/容量错误，不截断、不删准则或自动缩范围。不会把全部SourceArtifact.content作为控制字段回灌。
文字工具：实际输入、保存与变更检测
新绑定路径
text_work.authority在服务器bound Writer新契约存在时，加入本次任务goal、C1完整五字段/身份、适用Criterion完整payload及关联Requirement正文。现有goal/scope/instructions/guidance保持原权威含义。
旧模式路径
没有新binding时authority返回原来相同结构；不因全局C1头出现而修改历史text-work packet。
原文供给
C1 source依据和material_refs只提供源版本/定位信息；原标准/表样正文由Writer明确选入input_refs/source_selections等，不能把完整来源仅凭存在就算供给，也不自动灌全部文件。
解析和保存
produce/receipt/adopt使用同一authority解析；既有parse、output_count、schema、精确payload/index/CAS规则不变。
变更检测
新调用检查C1解释/相关依据是否仍与绑定的语义摘要一致；发生实质变化时对新的生成/采纳明确报stale，让Agent重新对齐。时间、预算计数、无关对象变化不应触发失效；旧业务成果不自动删除或作废。
生成期间要求变化
若生成完成后C1相关含义/已发布依据改变，不自动把旧候选作为新要求下成果采纳；保留原响应/receipt，禁止据此自动再发模型。
限制
不改现有材料64k准入、模型容量或provider限制，也不把这些限制解释为业务范围上限。新commission增加的实际上下文成本须如实可见，本批不作性能收益承诺。
