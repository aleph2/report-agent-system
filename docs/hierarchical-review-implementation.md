# 分层审核实现记录 v0.1

2026-09-30。依据《文档生成与分层审核系统实施设计 v1.0》。当前阶段为完整主干建设，尚未进行质量晋级。

## 已实现

- 在独立 SQLite 中追加对象、关系、快照、审核与处理记录；保存前版、责任方、摘要、UTC 时间和操作回执。批量事务、并发冲突、幂等重放、失败/未知回执分别处理。
- 标准、内容和审核写权限由服务端角色绑定。原生局部委派返回审核记录，不触发作者修订；最终审核继续使用 DeepAgents 原生入口和反馈路由。
- 判定、执行覆盖、处理状态分离。未执行保留 null；转交不必指定接手方；处理完成不代表修复。同版本已确认违例需要有据修订或由原审核责任方显式纠正。
- 审核绑定内容/标准版本；内容、导出、渲染适用性按单项记录区分。支持变更影响候选、显式局部审核复用及版本复查。
- 固定快照导出 DOCX，保存多对多映射及未呈现依赖命题。实际 LibreOffice 渲染绑定导出摘要，Windows 与 WSL 调用本机 LibreOffice 均已验证。读取 OOXML 与视觉模型观察分别提供。
- 新角色提示词采用公共约束、稳定职责、任务输入和工具契约；没有固定四层调用序列或每节点智能体。新路径不启用知识图谱服务。

## 启用与观察

在**新建的独立项目** manifest 中设置 `"content_contract": "hierarchical-review-v1"`，然后沿用 `report-agent report-run --project ...`。原项目不自动迁移。

`report-agent report-status --project ...` 返回内容交付身份和实际审核记录；`report-agent content-delivery --project ... --output report.docx` 可取出已选导出文件。此实现先接后端和 CLI，既有网页的旧稿列表尚未适配新内容对象。

模型连接仍使用现有运行配置；没有改动用户的 API key、服务地址或模型选择。视觉工具仍依赖现有视觉服务能力，连接不可用时保留执行失败，不声称页面已核验。

## 验证及边界

新增测试覆盖不可变版本、并发提交、闭包/包含环/游离正文、权限、三态与 null、转交、同稿重试、局部反馈、原生修订复查、历史违例、不同导出和渲染的适用性。脚本模型只验证框架交接，不能证明真实 LLM 的审核能力。

最终验证：203 项相关测试通过（166.81 秒），包含新内容/原生运行测试及既有 DeepAgents、验收反馈、权限、导出、来源检索、状态投影回归；`git diff --cached --check` 通过。CLI 已实际取出选定的完整报告，审核字段保持 null，没有伪造通过。

原有真实完整报告的 18,934 字正文被逐字保留为 35 个正文块，加报告根共 36 节点，关联 6 项原标准和 9 份来源，导出并渲染为 21 页。保留检查在 `.runs/task055/real-report/`；未导入历史审核，也未追认生成时采用来源。Main 抽看第 1、11、21 页，仅作渲染冒烟检查，不是全页视觉验收。

实际参与：Main 实现和执行验证，`/root/design_alignment_v1` 独立只读复核。其提出的同稿恢复、跨导出适用性、历史违例覆盖及游离正文问题均按 P2 修正并加入回归。范围是机制与草稿诊断；不把设计一致性当作质量认可。

最终聚焦复核确认上述版本隔离漏洞已修正，本检查范围未发现剩余 P1/P2；独立复核检查了代码及测试内容，测试由 Main 执行。旧接口回归中暴露的测试替身无 Store 兼容问题亦已修正。Git 提交只纳入本轮变更，043 原有未提交工作保留在工作区。

真实报告检查首次在导出时发现嵌套 Workspace 初始化争用事务（P2，阻断该导出，其他记录安全保留）。已改为只读来源视图；确认旧操作无已发布导出后用同一 operation_id 恢复，完整导出和渲染成功。

## 仍需完成的验收

本轮未启动付费模型实验。真实模型自主生成内容树、审核反馈后的修复收益，以及另一份未参与开发报告的迁移效果，尚未验证。自动审核可靠性、全页视觉质量和正式模板符合性尚未获认可。

下一步在固定模型和参数下，预先声明样本/重复次数/判据，比较旧全文审核与新分层方案的漏检、误报、误改、覆盖和最终遗留缺陷。保留原始输入、公开输出、实际工具观察及用量；不向审核模型提供注错清单。
