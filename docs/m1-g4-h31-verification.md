## Behavior

The existing shared completeness check refuses each `included=false` candidate
unless at least one of its own structured source citations matches an exact source
artifact version and physical page in verified direct-return records. Direct text
blocks, page inspection and image observations count. Search snippets and text
analysis helper inputs do not. Partial text or a cropped/incomplete image return
can satisfy this one-page condition; it does not establish whole-page reading,
comprehension or adequate engineering evidence.

The gap code is `EXCLUSION_SOURCE_NOT_DIRECTLY_RETURNED`; the gap identifies the
candidate and its cited source references, locators and parsed pages. The same
check applies at submission/saving, checkpoint request, approval/replay and writer
authorization, and the existing assessment/export callers. Plain-text claims of
owner approval, `origin=customer`, an unrelated page or an unrelated source do not
provide an exception. Citations without a physical page do not earn page credit.

No new override parameter is exposed. An unread candidate remains included pending
owner review; at the checkpoint the owner can record a reduction with a reason.
The immutable proposal remains unchanged. The existing operator-owned decision
removes the object from required downstream coverage, and its ID, label and reason
are shown under “用户排除决定” in the saved confirmation checklist. An old unread
exclusion must be corrected before a new checkpoint; it is not silently approved.

The guard reuses H3's receipt verification and skips physical PDF page-count work.
Default brief generation still reports page totals. No new ledger, model call,
permission, agent prompt, requirement classification or reading sequence is added.
The separate H3 P3 suggestions concerning key-range scans and shorter briefs are
deferred.
